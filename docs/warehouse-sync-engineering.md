# TC Cloud Warehouse 与多设备同步工程方案

最后更新：2026-11-12  
实施状态：进行中

## 1. 目标

天创云端使用一个默认名为 `TC-cloud-Warehouse` 的主仓库承载同一用户的多个资料库；用户可以修改仓库名。一个资料库可以同时绑定 GitHub、WebDAV、私人服务器、NAS、本地磁盘和移动硬盘等多个备份目标。

系统需要维护稳定的账户、设备、资料库、连接、目标和同步版本模型，不能再用“一个界面卡片等于一个已完成后端能力”的方式判断完成度。

## 2. 独立概念

### 2.1 用户身份

天创云端用户拥有稳定的应用级用户 ID。GitHub、X/Twitter、YouTube、Facebook 等属于可绑定身份，不等于备份目标。

跨平台身份绑定需要 OAuth 应用、回调服务、服务端账户映射、令牌撤销和账户恢复。本地 Electron 应用在没有这些外部条件时不得展示假登录或宣称已经绑定。

### 2.2 存储连接

存储连接保存“如何访问某个平台”：GitHub 账号、Git/Gitee 凭据、WebDAV、SFTP/S3、NAS 或本地磁盘。密码和令牌只进入系统凭据能力，不进入仓库、日志或渲染层 localStorage。

### 2.3 存储目标

目标是连接上的具体位置，例如：

- GitHub 账号 A 的 `TC-cloud-Warehouse`；
- WebDAV 连接 B 的 `/TC-cloud-Warehouse`；
- 私人服务器 C 的 `/srv/tc-cloud`；
- 移动硬盘 D 的 `Backups/TC-cloud-Warehouse`。

### 2.4 备份策略

备份策略把资料库映射到一个或多个目标。各目标独立记录确认版本；一个目标成功不能把其他失败目标标记为成功。

## 3. Warehouse 目录

```text
TC-cloud-Warehouse/
├─ .tc-cloud/
│  ├─ warehouse.json
│  ├─ devices/
│  │  └─ <device-id>.json
│  └─ libraries/
│     └─ <library-id>.json
└─ libraries/
   └─ <library-id>/
      └─ files/...
```

资料库使用稳定 ID 作为目录名，显示名称可以修改。默认不使用“一资料库一分支”，因为 Git 分支不是可靠的存储命名空间，并发同步、恢复和历史清理更复杂。

普通 Git 适合文档、源码和笔记。大型视频、压缩包和高频二进制文件应允许路由到 WebDAV、对象存储或私人服务器；统一 Warehouse 不代表所有数据必须强塞进普通 Git 历史。

### 3.1 中文名称与远端安全键

本地资料库始终保留用户设置的中文显示名。GitHub 仓库名以及 WebDAV、NAS、私人服务器上的目录名使用 ASCII 安全键：先把中文转为无声调拼音，再附加由“原始显示名 + 稳定资料库 ID”生成的 12 位十六进制后缀。例如 `干物妹 小埋` 可映射为 `gan-wu-mei-xiao-mai-567366cfdddd`。第一次生成后，这个键作为资料库级 `remoteKey` 持久化并发布到 Warehouse；后来修改显示名或删除最后一个目标都不会改变它。旧版本资料库会从已有 Git、WebDAV 或磁盘目标恢复一次并写回，避免升级后出现第二个后缀不同的远端。

不能只做字符删除或把每个不支持的字符替换为 `-`，否则多个中文名会同时退化为 `---`；也不能只使用拼音，因为同名资料库和同音异字仍会冲突。远端键最长 100 个字符，并只允许 ASCII 字母、数字、点、短横线和下划线。

原始显示名写入状态文件的 `workspaceName`。新设备恢复后使用它还原界面名称，而不是把远端拼音键当作本地名称。已有本地镜像目标继续沿用旧目录，避免升级后静默切换备份位置；只有新建目标使用安全键。

## 4. 设备注册

每次安装首次启动时生成稳定 `deviceId` 并保存在本机。设备名称由用户设置，在同一账户范围内唯一；设备名称只用于显示，不能代替设备 ID。

每台设备独立写入 `.tc-cloud/devices/<device-id>.json`，界面将这些文件汇总为一个设备中心，避免多设备争写同一个 `devices.json`。

```json
{
  "schemaVersion": 1,
  "deviceId": "稳定设备ID",
  "deviceName": "宿舍电脑",
  "deviceModel": "ASUS ...",
  "platform": "Windows 11",
  "appVersion": "0.2.0",
  "registeredAt": "ISO-8601",
  "lastSeenAt": "ISO-8601",
  "lastSyncAt": "ISO-8601",
  "syncState": "idle",
  "lastSyncResult": "success"
}
```

`online/offline` 不作为永久事实写入。客户端根据 `lastSeenAt` 和心跳阈值推算“在线、最近活跃、离线”。只有 GitHub 文件而没有实时服务时，只能提供最近活跃状态，不能宣称实时在线。

新登录设备先读取设备目录：本机仍持有相同 `deviceId` 时恢复原名称；全新安装时由用户选择注册新设备或认领已有设备。不得根据设备型号自动认领，避免两台同型号设备被误合并。

## 5. 统一同步状态文件

每个资料库使用一个隐藏状态文件：

```text
<workspace>/.tianchuang-cloud/state.tc
```

状态目录不进入普通文件扫描和文件监听；同步引擎显式读取和上传，避免状态文件更新再次触发同步循环。

```json
{
  "schemaVersion": 2,
  "workspaceId": "稳定资料库ID",
  "workspaceName": "课程资料",
  "revisionId": "32位小写十六进制字符串",
  "parentRevisionId": "上一个共同版本ID",
  "generation": 28,
  "deviceId": "产生版本的设备ID",
  "createdAt": "ISO-8601",
  "files": {
    "课程/第一章.md": {
      "fileId": "稳定文件ID",
      "size": 18243,
      "mtimeMs": 1793601000000,
      "sha256": "内容哈希",
      "deleted": false
    },
    "课程/旧笔记.md": {
      "fileId": "稳定文件ID",
      "deleted": true
    }
  },
  "targetHeads": {
    "github-target-id": "revisionId",
    "webdav-target-id": "older-revisionId"
  }
}
```

`revisionId` 使用 16 字节密码学随机数并编码为 32 位十六进制字符串。随机码只负责唯一标识，不能判断因果；`parentRevisionId`、共同基线和文件哈希负责判断继承与冲突。

`workspaceName` 是显示元数据。即使普通文件没有变化，名称映射发生变化也必须生成同步提交；状态文件与每目标基线必须进入同一个 Git 提交，不能在 push 后再留下一个待提交的基线变更。

## 6. 冲突判断

以双方上一次共同确认的基线版本为准：

1. 本地和远端版本相同：无操作。
2. 只有本地相对基线变化：上传。
3. 只有远端相对基线变化：下载。
4. 两边变化但修改不同文件：自动合并并生成新版本。
5. 两边修改同一文件且哈希不同：展示冲突。
6. 一边删除、另一边修改：删除与修改冲突，必须确认。
7. 版本不同但内容哈希相同：合并状态，不重复传输。

文件大小和修改时间仅作为提示，不能作为相等证明。当前正确性优先实现会为状态快照中的普通文件计算 SHA-256；后续如增加哈希缓存，缓存键也必须包含可验证的内容身份，不能仅凭大小和 mtime 复用。删除使用 tombstone，不能依靠“文件不存在”静默传播。

同步计划必须包含基线版本和远端版本指纹。执行前再次核对；任何一方变化时废弃旧计划并重新生成，特别是删除计划。

## 7. 原子性与多目标

1. 先扫描并生成候选状态。
2. 上传或下载普通文件。
3. 校验文件数量、大小和必要哈希。
4. 最后原子写入状态文件。
5. 只有目标确认完成后才推进该目标的 `targetHead`。
6. 任一目标失败不回滚已成功目标，但必须保留清晰的部分成功状态和可重试计划。

状态文件和普通文件写入均使用临时文件加原子替换；WebDAV 普通文件与状态文档都先上传到同目录临时路径再 MOVE，失败时保留旧远端文件并清理临时项。WebDAV 与磁盘/NAS 镜像的受管删除都先 MOVE/重命名到专用隔离临时项，状态提交成功后才清理；提交失败会回滚原名，进程中断后下一次规划会自动恢复。普通上传遗留的临时项不会被当作用户文件恢复。Git 使用一次提交承载文件与状态变更。

## 8. 安全约束

- 状态文件路径必须验证，拒绝绝对路径、`..` 和状态目录自引用。
- 本地镜像子目录和 WebDAV 远端路径必须在后端再次验证；拒绝路径穿越、符号链接逃逸以及资料库与镜像目录互相包含造成的递归备份。
- 状态文件不保存密码、令牌、WebDAV 密钥或社交平台凭据。
- 远端状态是不可信输入，必须校验 schema、字符串长度、十六进制格式和条目数量。
- 资料库 ID、设备 ID 和文件 ID 不使用用户可控路径片段。
- 覆盖、删除和以远端为准前保留恢复副本。

## 10. 验收

- lint、单元测试、构建全部通过；不以构建通过代替同步正确性。
- 覆盖同文件双端编辑、同大小内容变化、删除与修改、计划过期、磁盘写满、原子替换失败、替换前独立进程强杀、Git push 拒绝、WebDAV MOVE 拒绝、多目标部分失败、WebDAV 服务端传输中强杀与恢复重试；完整应用多文件传输强杀和物理磁盘拔出仍需专项集成测试。
- WebDAV 使用可控测试服务器或协议 mock；Git 使用临时裸仓库；磁盘镜像使用临时目录。
- 自动同步遇到暂时离线的移动盘、NAS 或已改名目录时静默等待；手动同步仍应明确报错。
- 不生成安装包，除非明确进入发布阶段。
