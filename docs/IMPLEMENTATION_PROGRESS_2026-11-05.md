# 天创云端实施进度（2026-11-05）

本文记录 2026-11-02 进度之后的增量。它只陈述已经落到代码并完成验证的内容，不等同于外部服务兼容性或发布验收。

## 本轮完成

### 全局存储连接生命周期

- 设置页可检查、编辑 Git、WebDAV 和本地磁盘连接；编辑后的名称、单文件限制与连接配置会传播到所有已绑定目标。
- 正在被目标使用的连接禁止删除；未使用连接要求二次点击确认，确认状态五秒后自动失效。
- WebDAV 编辑时密码留空会保留原凭据，填写新密码会轮换 `safeStorage` 加密凭据。删除连接时只清理不再被任何连接或目标引用的密钥。
- Git、WebDAV 和磁盘健康检查均有十五秒上限，并在设置页展示成功或失败原因；不会把超时伪装成可用。
- 编辑表单和图标按钮补充可访问名称、忙碌状态、结果反馈与禁用原因。

### Warehouse 连接隔离修正

发现并修复一个高风险前提错误：全局 Warehouse 连接不应保存首个资料库的 `libraryId`。旧逻辑在另一资料库复用该连接时，可能让两个资料库指向同一 Warehouse 目录。

现在：

- 全局 Warehouse 连接模板不保存 `libraryId`；读取旧记录时会惰性清理该字段。
- 连接绑定到资料库时，以当前资料库稳定 ID 生成该目标的 `libraryId`。
- 编辑共享 Warehouse 连接时保留每个目标自己的 `libraryId`，不跨资料库覆盖。
- 新增纯逻辑测试覆盖使用计数、配置传播、WebDAV 密钥引用和 Warehouse 资料库隔离。

### 故障注入与确认状态保护

- 修复普通 Git 同步在 push 成功前就永久推进本机状态的问题。远端拒绝 push 时，现在会撤销本次同步提交、恢复上一次已确认的 `state.tc`，且不写入目标基线；用户文件仍保留为可重试的本机内容。
- 本机状态和每目标基线统一通过随机临时文件加原子替换写入。模拟 `ENOSPC` 和替换中断时，旧状态保持不变，本次临时文件会尽力清理。
- WebDAV `state.tc` 不再直接覆盖：先上传临时状态，再使用 MOVE 发布。MOVE 被服务器拒绝时清理临时远端状态，本机 revision 和目标基线均不前移。
- 故障注入验证了 Git 裸仓库拒绝 push、WebDAV 服务器拒绝 MOVE、磁盘写满和原子替换中断四条失败路径。
- 本地镜像上传与恢复、Warehouse 缓存复制和 WebDAV 下载也改为同目录临时文件完成后再替换；复制失败时保留原文件并清理本次临时文件，避免半写文件被误当成完整版本。
- 新增独立子进程强杀测试：子进程写完临时文件但尚未替换正式文件时被终止，正式文件仍保持已确认内容。来不及清理的 `.tianchuang-<32hex>.tmp` 残留会被资料库扫描明确忽略，不会传播到其他目标。

## 仍未完成，不能宣称已实现

1. X/Twitter、YouTube/Google、Facebook 等应用级账户绑定仍缺 OAuth 应用、回调域名、隐私政策和服务端账户映射。
2. 设备状态目前是最近活跃与同步结果；真正在线状态仍需心跳或 WebSocket 服务。
3. SFTP、S3/OSS 等私人服务器原生提供器尚未实现；当前可用范围是 Git、WebDAV 和本地或已挂载磁盘。
4. Nextcloud、群晖、坚果云等真实 WebDAV 服务的配额、锁定、断网恢复与 MOVE 行为尚未形成兼容矩阵。
5. 磁盘写满、Git push 拒绝、WebDAV MOVE 拒绝及单文件替换前的独立进程强杀已有自动故障注入；完整应用在多文件传输中被强杀、Git 远端已接受 push 但本机基线落盘失败、残留临时文件的定期回收，以及超大 Warehouse 历史清理仍需专项测试。

## 下一步建议

优先补完整应用多文件传输强杀和“远端已确认、本机基线落盘失败”的恢复测试，再用至少两个真实 WebDAV 服务建立兼容矩阵。应用级账户、社交 OAuth 与实时在线心跳应作为独立后端工程推进，不应在桌面端增加没有真实后端的绑定入口。
