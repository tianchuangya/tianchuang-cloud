## 本轮发现并修复的真实缺陷

GitHub 对新建空仓库的 Contents API 返回 `This repository is empty.`，旧实现只把 `Not Found` 当作可初始化的缺失资源，因此出现“仓库已创建但第一次配置发布失败”的半完成状态。

修复后，这两种响应都进入首次初始化路径，但认证失败和网络错误仍会继续抛出，不会被静默吞掉。新增 3 个回归用例覆盖空仓库、普通 404 和不可隐藏的认证/传输错误。

本轮实机验证还发现两个边界问题并已修复：

1. 普通文件不变时，旧规划器会把 `workspaceName` 补录误判为“无需传输”；现在名称元数据变化会单独形成上传计划。
2. Git 目标基线原先在 push 成功后才写入，留下一个新的受跟踪改动并触发第二次同步；现在 `state.tc` 与目标基线进入同一个提交，push 失败时两者一起恢复。
3. 多目标同步原先遇到首个异常就中断，后续健康目标不会执行；现在目标按顺序隔离执行、收集全部失败，成功目标仍推进自己的状态，最终用汇总错误标记资料库。待确认目标也会在全部目标处理后重新标记为 `attention`，不会被后续成功覆盖。
4. WebDAV 普通文件原先直接覆盖目标，连接中断可能破坏旧版本；现在普通文件和状态文档都使用同目录临时上传 + MOVE。读取失败或源文件中途消失会明确失败，不再静默跳过并错误推进状态。
5. 本地镜像与 WebDAV 配置新增后端路径边界校验，拒绝 `..`、绝对子路径、符号链接逃逸和资料库/镜像互相包含导致的递归备份。
6. 旧 WebDAV 没有状态哈希时，同大小内容变化可能漏检；现在规划与执行复核都会计算实际远端 SHA-256。此策略优先保证正确性，后续可用可信 ETag/哈希缓存降低大资料库的网络读取成本。
7. 实机界面复核发现旧仓库虽然已迁移为拼音名，但新增目标会按资料库 UUID 重新计算另一个后缀，可能误建第二个仓库；现在旧资料库会从已有目标恢复并持久化同一个 `remoteKey`，界面建议值与现有远端完全一致。
8. WebDAV 原先在上传与状态发布之前直接删除受管远端文件，后续 MOVE 失败会留下“状态未提交、文件已丢失”的半事务；现在删除先进入可回滚隔离区，状态提交失败立即恢复，进程中断后下一次规划也会自动恢复。
9. 磁盘/NAS 镜像存在相同的先删后提交风险；现在也采用隔离改名、状态提交、成功清理三段式流程，中断遗留项不会被当成用户文件并会在下次规划恢复。
10. `.tc`、Warehouse 和 WebDAV 状态读取原先会把部分权限、网络或 I/O 异常吞成“文件不存在”；现在本机只接受 `ENOENT`、WebDAV 只接受明确 404，状态读取和远端 `stat` 的其他失败都中止同步。

拼音转换最初被静态打进渲染层，使主前端包从约 417 kB 增至约 705 kB。现已改为 Electron 主进程提供命名建议，渲染层主包恢复到约 417 kB。
