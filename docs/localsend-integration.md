# LocalSend 兼容模块接入方案

## 1. 产品定位

模块名称暂定为“附近传送”。它负责在同一局域网内发现设备、发送文件和接收文件，与云端同步和备份目标分开：

- 云端同步解决持续版本与多目标备份；
- 附近传送解决一次性的高速点对点交付；
- 接收到资料库目录内的文件后，再由现有同步引擎纳入版本状态。

## 2. 上游项目

- 项目：[LocalSend](https://github.com/localsend/localsend)
- 许可证：Apache License 2.0
- 本地参考源码：`localsend-main/`
- 当前主线架构：Flutter 界面 + Rust 协议核心；协议 v2 使用 HTTPS、设备证书指纹与 UDP 组播发现。

天创云端不会嵌入 LocalSend 的 Flutter 界面。优先方案是让 Electron 主进程通过受控的 Rust sidecar 或稳定绑定使用 LocalSend 协议核心，渲染层只显示天创云端自己的设备列表、授权确认和传输状态。

## 3. 当前实现（2026-11-13）

- Electron 主进程启动并监管 `tc-localsend-sidecar`，渲染层不接触证书私钥或任意本机路径；
- 侧栏“附近传送”提供在线设备、手动探测、文本发送、文件/文件夹选择、接收确认和传输状态；
- 固定的 LocalSend Rust core 最小快照位于 `native/vendor/localsend-core`，sidecar 通过 JSON Lines 与主进程通信；
- 接收文件先写随机 `.part` 文件，校验成功后原子改名；路径分段清理并为重名文件分配唯一名称；
- 53317 被官方 LocalSend 占用时自动选择 53318–53327，同时保留标准组播发现；
- 安装构建会编译 release sidecar，并把 Apache 2.0 许可证放入 `resources/licenses`。

### 已验证

- 两个独立 sidecar 在 53417/53418 双向发现；
- 中文文本发送成功；
- 中文文件名文件发送、接收及内容校验成功；
- 天创云端与本机官方 LocalSend 客户端同时运行：自动避让端口、成功发现、中文文本实际送达并完成发送会话；
- Electron preload 桥、lint、TypeScript/Vite 构建及项目测试通过。

### 尚未完成的发布验证

- macOS/Linux sidecar 原生构建、签名与安装包运行；
- 不同实体设备之间的大文件、断网、睡眠唤醒和低磁盘空间矩阵；
- 官方 LocalSend 多版本（Android/iOS/macOS/Linux）互操作；
- 可信设备持久化、黑名单和接收目录自定义。

## 4. 接入阶段记录

### 阶段 A：协议验证（核心完成）

- 构建独立 LocalSend core/CLI 测试程序；
- 与官方 LocalSend Windows 客户端双向发现；
- 小文件、大文件、中文文件名和文件夹双向传输；
- 验证证书指纹、拒绝、取消、超时和断线恢复。

### 阶段 B：Electron 后端（完成）

- 主进程管理发现服务和接收服务生命周期；
- IPC 只暴露经过验证的设备信息与传输操作；
- 接收文件先写临时目录，用户确认目标后原子移动；
- 限制文件名、相对路径、会话大小和并发数，拒绝路径穿越。

### 阶段 C：产品界面（完成首版）

- 侧栏增加“附近传送”；
- 展示在线设备、可信指纹、发送队列和接收请求；
- 未完成协议服务前不显示假入口；
- 传输结束后可选择“加入资料库”，但不得自动覆盖现有文件。

## 5. 开源合规

- README 明确感谢 LocalSend 项目和贡献者；
- 如果分发或修改其源码/二进制，安装包中保留 Apache 2.0 许可证副本及上游版权声明；
- 修改过的上游文件必须明确标记变更；
- 天创云端名称、图标和界面不得暗示自己是 LocalSend 官方版本。

## 6. 风险

- UDP 53317 和入站 HTTPS 可能触发防火墙授权；不能静默放宽系统防火墙。
- Electron 与 Rust sidecar 增加三平台构建、签名和自动更新成本。
- LocalSend 主线协议正在演进，必须固定兼容版本并通过官方客户端互操作测试。
- “附近设备”不是账号设备列表：离线设备档案与实时局域网发现应保持两套状态模型。
