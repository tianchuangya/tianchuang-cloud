## 1. 项目定位

天创云端（Tianchuang Cloud）是一个 Electron + React 的跨平台文件同步与资料库管理桌面应用，目标平台为 Windows、macOS 和 Linux。

项目不只是“把文件推送到 GitHub”，而是希望形成统一的数据管理入口：

- 一个本地资料库可同时备份到 GitHub、Gitee、通用 Git、WebDAV、本机磁盘、移动硬盘和已挂载网络磁盘。
- 同步前先比较本地与远端状态，没有变化时不创建空提交，也不重复上传。
- 远端较新、本地存在独有文件或即将传播删除时，必须先向用户展示差异并等待确认。
- 支持新设备恢复、私人配置仓库、多设备资料库发现和后续的多账号/团队协作。
- 长期方向包括文件预览与编辑、Markdown 资源管理、语音输入和 AI 文件助手。

界面方向是偏 Apple 桌面应用的透明毛玻璃：平滑圆角、半透明材质、柔和阴影、克制动效和清晰的信息层级。视觉效果必须服务于任务，不能把同步软件做成只有演示动画的页面。

## 3. 技术栈与入口

### 渲染层

- React 19、TypeScript、Vite。
- `motion`：弹窗、列表与页面过渡。
- `gsap`：部分参考动效和滚动组件。
- `ogl`：当前 GPU 背景和水波效果。
- `lucide-react`：应用图标。

主要文件：

- `src/App.tsx`：资料库首页、目标管理、设置、冲突确认、进度和主要弹窗。
- `src/App.css`：全局桌面布局、玻璃材质、设置中心和资料库视图。
- `src/components/cursor-preferences.ts`：指针、背景、启动动画和资料库视图偏好。
- `src/components/InteractiveBackdrop.tsx`：背景图与动态背景效果的组合入口。
- `src/components/WorkspaceShowcases.tsx`：手风琴与深度轮播资料库视图。
- `src/components/GridMotion.tsx`：有序动态网格资料库视图。
- `src/components/StartupExperience.tsx`：启动动画、加载进度和任意键/鼠标进入。
- `src/components/CursorExperience.tsx`：自适应矩形指针和点击反馈。

### Electron 主进程

- `electron/main.ts`：窗口、托盘、通知、IPC、目录选择和文件监听。
- `electron/preload.ts`：最小权限渲染层 API。
- `electron/sync-service.ts`：同步计划、自动同步与活动记录。
- `electron/providers/git.ts`：Git/GitHub/Gitee 同步。
- `electron/providers/webdav.ts`：WebDAV 同步。
- `electron/providers/local.ts`：本地、移动和网络磁盘镜像。
- `electron/cloud-config.ts`、`electron/config-service.ts`：私人配置仓库和新设备恢复。
- `electron/store.ts`：本地状态存储。
- `electron/covers.ts`、`electron/backgrounds.ts`：资料库封面和自定义背景资产。

## 4. 已完成能力

### 同步与资料库

- 按钮选择和拖放导入文件夹。
- 左侧资料库列表、右键设置封面、重命名和移除。
- 自动识别资料库根目录的 `.tianchuang-cover.*`、`tianchuang-cover.*`、`cover.*`、`folder.*`。
- 封面支持 16:9 拖动裁剪和缩放，保存为资料库根目录下的 1280×720 PNG，相对资料库同步。
- GitHub 浏览器认证、状态检查、自动创建公开/私人仓库、已有仓库绑定和首次推送。
- GitHub、Gitee、通用 Git、WebDAV、本地磁盘、移动硬盘、网络盘/NAS 多目标同步。
- 自动同步总开关、文件变化同步、应用聚焦同步、同步延迟和错误提醒冷却时间。
- Git 分支状态与大文件预检；远端较新时支持保留本地独有文件或以远端为准。
- 覆盖前创建恢复副本；分叉或冲突时停止自动处理。
- Git/WebDAV/磁盘的受管云端删除传播，必须先列出文件并由用户确认，自动同步不得静默删除。
- GitHub 协作者邀请与只读/可更新权限。
- 私人主配置仓库、设备配置上传和新设备资料库恢复提示。配置中不保存密码、令牌或 WebDAV 密钥。

### 当前界面与视觉

- 系统标题栏替代方案、圆角应用边缘、Windows Acrylic/macOS Vibrancy 和深色玻璃层级。
- 资料库视图：玻璃卡片、动态网格、手风琴封面、深度轮播。
- 背景图与动态效果完全分离；背景图支持自定义、恢复默认、模糊度和不透明度。
- 动态背景：水波折射、轻量侧光、轻量粒子、SoftAurora、Iridescence、WebThreads、Topography。
- 设置中的动态背景选项停留 1 秒后进入沉浸预览；设置窗口隐藏，鼠标移动后恢复。
- 背景效果支持搜索、按需加载、减少动态效果，并在不可见时暂停 OGL 循环。
- 矩形/系统指针切换；矩形指针会读取交互控件边界，自适应宽高。
- 空白区域保留中心点和向中心收束反馈；吸附控件时中心点消失。
- 左右键具有不同矩形回波；烟花为白色并已降低速度。
- 流体彩雾、点击烟花、AnimatedContent、FadeContent、LogoLoop。
- 启动画面含加载进度；加载完成后任意键或鼠标点击进入，不使用“进入”按钮。
- 设置中心已有顶部大类与左侧子类的基础十字结构。
- “关于”中包含项目仓库、作者 GitHub、头像和个人博客。

- `DepthCarousel`：已适配为真实资料库深度轮播。

注意：`WebThreads.txt` 和 `Topography.txt` 中的完整参数版本尚未全部暴露。当前应用使用的是性能更克制的适配版。如果后续加入高级调节面板，应复用现有按需加载和 WebGL 清理约定，不能同时常驻多个 GPU 上下文。

### 未接入的资料库与导航样式

- `OptionWheel`：弧形唱片/阶梯式资料库视图，需要支持封面、文字、滚轮/拖拽和有序浏览。
- `InfiniteMenu`：无限画布，但必须保持确定的线性顺序；向同一方向持续移动应能遍历全部资料库。
- `FolderFloat`：悬停资料库后显示内部主要文件；排序方式包括大小、名称、修改日期和用户自定义。
- `GlassIcons`：目前只有项目自有玻璃卡片，没有完整复刻其折射、前后层与标签动画。
- `BranchedMenu`：用于资料库内部路径树和当前路径指示。

### 未接入的设置、输入和状态组件

- `Stepper`：首次使用引导。
- `GlideSelect`：下拉选择。
- `JellyRadio`：设置顶部大类或模式切换。
- `RubberSegment`：设置左侧纵向子类切换，需要从横向适配为纵向。
- `CodeSlots`：本地应用锁或验证码输入。
- `BellToggle`：同步、AI、声音、系统通知偏好。
- `ThoughtLine`：同步步骤、耗时、成功和错误状态。
- `CallChip`：单个同步任务进度与重试。
- `SwipeToast`：右下角完成/失败/可撤销通知。
- `SwipeRow`：顶部通知中心，支持自动过期和手势删除。
- `VoicePill`：语音转文字或语音附件。
- `PromptBar`：AI 文件助手输入栏。
- `WarmTooltip`：Markdown/文本编辑工具提示。
- `FuseButton`：危险操作倒计时确认。
- `SlideCommit`：高风险同步前滑动确认；不能替代明确的差异说明。

### 未接入的 GPU 背景

- OGL 优先：`MoltenMetal`、`Scanner`、`Ferrofluid`、`Prism`、`SideRays`、`LightRays`、`LineWaves`、`GradientBlinds`、`PixelSnow`、`Galaxy`、`Threads`、`Orb`。
- 高性能预算：`AeroShards`。
- 需要新增 Three.js/后处理依赖：`LiquidEther`、`PixelBlast`。
- 需要 React Three Fiber：`Beams`。
- GPU 版 `Particles` 尚未接入；当前只有轻量 CSS 粒子。

这些背景都应该进入“设置 -> 外观与动态 -> 背景与效果”，继续使用搜索框。背景效果不是背景图，不能清除或替换用户的自定义背景图。

## 6. 未完成产品规划

完整状态以 `docs/feature-roadmap.md` 为准。下面是接手后的主要工作包。

### P0：同步闭环，优先级最高

1. 多云迁移：从 Git/WebDAV/磁盘读取，迁移到另一个目标；先展示计划、大小、目标容量和冲突。
2. 统一差异模型：把 Git 已有的“远端较新 + 本地独有文件”决策扩展到 WebDAV 和磁盘。
3. 统一大文件预检：所有提供器都应给出大文件列表、限制原因和更换目标建议。
4. 多账号：主账号之外允许绑定多个 GitHub/Git/Gitee 身份；令牌必须进系统凭据存储，不能进配置 JSON、日志或渲染层 localStorage。
5. 团队协作继续完善：共享资料库订阅、所有者权限、对方只读/可更新、更新通知和撤销访问。
6. 用户最初提出“主配置仓库管理全部资料库连接，并以分支对应 Git 同步项目”。当前只完成安全的配置元数据仓库；“每个同步项目使用配置仓库分支”的拓扑尚未实现，需要先确认是否值得增加复杂度。

### P1：文件浏览与编辑

1. 资料库内部文件树、路径面包屑和 `BranchedMenu`。
2. 图片、Markdown、纯文本、PDF、音频和视频预览；未知格式调用系统打开。
3. Markdown/纯文本编辑，保存前生成恢复副本。
4. Markdown 内嵌本地图片整理：为每个 Markdown 所在路径建立专用资源目录，将嵌入图片复制/转换并改写为可移植相对路径。不要把位图强制伪装为 SVG；只有确实适合矢量化时才转换。
5. 文件/文件夹增删改、移除资料库与删除云端备份必须区分，并使用明确确认。
6. `FolderFloat` 内部文件预览排序和用户自定义词条。

### P2：首次使用、设置与安全

1. `Stepper` 首次使用流程：GitHub 登录、私人配置仓库、导入资料库、选择同步目标、可跳过 AI。
2. 完善设置中心信息架构。建议顶部大类：启动、外观、资料库、同步、通知、AI、安全、账户、关于；左侧显示当前大类的子项。
3. 把零散原生 `<select>`、切换按钮和分段控件逐步统一为 `GlideSelect`、`JellyRadio`、`RubberSegment` 的项目化版本。
4. 本地应用锁：可跳过；设置后启动时验证。密码不得明文保存，应使用系统凭据能力和可靠的密钥派生。
5. 通知偏好：同步成功、同步失败、AI 完成、声音和系统通知分别控制。
6. 背景高级设置：每种效果可配置速度、密度、颜色、交互强度等，但默认值必须克制，并提供恢复默认。
7. 指针高级设置：矩形边框、吸附过渡、点击回波、烟花和流体参数独立配置。

### P3：状态与通知

1. 用 `ThoughtLine` 改造同步浮层，展示扫描、比较、上传/下载、完成/失败和耗时。
2. 用 `CallChip` 展示单个目标同步状态和重试。
3. 用 `SwipeToast` 统一右下角通知，并支持撤销适合撤销的操作。
4. 建立顶部通知中心，消息自动过期、可滑动删除，重要失败不能静默消失。
5. 自动同步失败提醒必须使用冷却时间，不能因路径改名或目标离线持续弹窗。

### P4：AI 文件助手，最后实施

1. 设置 Base URL、API Key、模型和推理强度；Key 必须进系统安全存储。
2. `PromptBar` 支持附件、停止生成、模型和推理强度。
3. 用户必须明确选择 AI 可以读取的资料库/文件范围。
4. AI 修改、移动、重命名或删除文件前，必须展示操作计划并再次确认。
5. 语音转文字与 `VoicePill` 共用录音权限、状态和失败恢复。

## 7. 已知边界与需要复查的地方

- `README.md` 的部分“当前完成度”描述落后于 `main`，例如仍只写两种资料库视图。后续稳定后同步更新 README。
- 当前主 bundle 构建会出现大于 500 kB 的 Vite 警告。GPU 组件已懒加载，但 `App.tsx` 仍很大；继续拆分设置、目标弹窗和资料库详情可以降低主包体积。
- 沉浸背景预览逻辑已经实现，但应补自动化 UI 测试：停留不足 1 秒不隐藏；满 1 秒隐藏；任意指针移动立即恢复；选择结果只在点击后持久化。
- 新增资料库视图在极窄窗口可用，但主要目标仍是桌面尺寸。每次改动后检查 1280×800、1440×900 和较窄侧栏布局。
- WebDAV 当前主要按大小判断变化，远端哈希比较尚未完成。
- Git 历史分叉时仍停止自动处理，不要未经用户确认自动 rebase 或强推。
- 首次连接“远端已有历史、本地尚未初始化”的文件夹仍需要先克隆再导入。
- 代码签名、Apple 公证、应用自动更新、端到端加密、S3/OSS 原生提供器和版本浏览尚未实现。
- 当前版本号仍为 `0.1.0`，后续主分支功能发布前需要决定是 `v0.1.1` 还是 `v0.2.0`，不要覆盖现有 `v0.1.0` 标签。

## 8. 设计与交互硬约束

- 背景图和背景动态效果必须分开存储与配置。
- 动态效果预览不得遮挡效果本身；当前约定为停留 1 秒隐藏设置、鼠标移动恢复。
- 资料库视图必须使用真实资料库与真实封面，不使用网络随机图或重复假数据。
- 用户封面保存在被同步资料库中，换设备后应继续可见。
- 自动同步不得静默删除远端文件，也不得在错误时高频弹窗。
- “移除资料库”“删除本地文件”“删除云端备份”是三个不同操作，文案和确认不能混用。
- 多账号令牌、WebDAV 密码、AI Key 和应用锁凭据不得明文保存。
- AI 或自动化执行文件修改前必须获得用户确认，并保留恢复路径。
- GPU 效果必须按需加载、支持 `prefers-reduced-motion`、暂停不可见渲染并在卸载时释放 WebGL 上下文。
- 不要把所有参考组件一次性堆进界面；每次完成一个功能组，补齐真实数据、空状态、键盘操作、退出路径和错误恢复。

## 9. 推荐的接手顺序

1. 先运行现有验证，确认环境与基线没有变化。
2. 为沉浸背景预览和偏好迁移补测试，并更新 README 当前能力。
3. 完成 P0 的跨提供器统一差异模型和统一大文件预检。
4. 拆分 `App.tsx`，再完善设置中心信息架构和通知系统。
5. 实现文件树、预览和 Markdown 编辑，再处理本地图片相对路径整理。
6. 接入剩余资料库视图和 OGL 背景，每组单独验证性能。
7. 最后实施语音与 AI；不得先放置没有真实后端的假按钮。

## 10. 开发、验证与提交

```bash
npm install
npm run dev

npm run lint
npm test
npm run build
```

当前测试基线：6 个测试文件、22 项测试通过。

每组功能完成后必须：

1. 运行 `npm run lint`、`npm test`、`npm run build`。
2. 在开发服务器中检查真实交互，不只看静态截图。
3. 检查正常桌面、窄窗口、减少动态效果和降低透明度。
4. 检查 Git 工作区，不覆盖用户已有改动。
5. 成熟功能提交并推送 `main`；没有明确发布要求时不要打安装包、不要创建标签。
